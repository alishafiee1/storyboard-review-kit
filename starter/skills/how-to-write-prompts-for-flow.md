# استاندارد پروژه‌های تصویر/ویدیو با Flow

## ۱) خط رفرنس‌ها (اول هر پرامپت)
- خط اول هر بلوک: `[REFS TO ATTACH: STYLE_ANCHOR| CH_AAA| LOC_CCC]`
- اسم‌ها دقیقاً برابر اسم فایل رفرنس. **قبل از هر اسم یک فاصله، بعد از اسم هیچ فاصله‌ای نه** (بدون فاصلهٔ قبلی، پنل رفرنس Flow باز نمی‌شود).
- `STYLE_ANCHOR` همیشه اول است. سقف رفرنس هر پرامپت ۱۰؛ بیشتر شد صحنه را به دو شات تقسیم کن.
- توی متن صحنه: اسم کاراکتر/وسیله + توضیح ظاهری کوتاه فقط در اولین ذکر. مکان و شیء (`LOC_`، `PROP_`) را با **کلمه** توصیف کن، نه با اسم (وگرنه اسم مثل تابلو روی تصویر نوشته می‌شود).

## ۲) هر بلوک پرامپت کامل و مستقل
- همه‌چیز داخل خود بلوک است؛ هیچ هدر یا متن مشترکی بیرونش نیست.
- ترتیب: خط رفرنس ← سبک ← قوانین ثابت ← قالب نوع تصویر ← `Subject:` ← `Reminder:` ← `Asset name` ← `Avoid:`. سبک **اول** می‌آید.
- بلوک‌ها انگلیسی‌اند، همه در `prompts/prompts.txt`، هر کدام با هدر `=== IMG001 ===` (جزو پرامپت نیست).

## ۳) نام‌گذاری
| چه چیزی | قالب | مثال |
|---|---|---|
| لنگر سبک | `STYLE_ANCHOR` | `STYLE_ANCHOR.png` |
| کاراکتر | `CH_NAME` | `CH_SCHUSTER.png` |
| وسیله نقلیه | `CAR_NAME` | `CAR_THOMAS.png` |
| مکان | `LOC_NAME` | `LOC_SWAMP.png` |
| شیء | `PROP_NAME` | `PROP_BICYCLE.png` |
| گروهی | `GRP_NAME` | `GRP_ALL_CARS.png` |
| تصویر صحنه | `IMG###_slug` | `IMG004_montezuma_stuck.png` |
| کلیپ | `VID###_slug` | `VID004_montezuma_stuck.mp4` |

رفرنس‌ها: حروف بزرگ و زیرخط، بدون فاصله، یکتا. `slug`: حروف کوچک و زیرخط. پسوند تصادفی Flow (`IMG004_x_edfa6fe0_2K.jpg`) قبول است؛ اسم پایه ملاک است.

## ۴) ساختار پوشه‌ها
```
review.html + click-for-review.bat + tools/   ← موتور (با tools/update.py به‌روز می‌شود، دستی ویرایشش نکن)
scenario/story.txt          ← تنها منبع سناریو
prompts/prompts.txt         ← پرامپت‌های تصویر
prompts/video-prompts.txt   ← پرامپت‌های ویدیو
images/refs/{STYLE,CH,LOC,PROP,GRP}/   ← رفرنس‌ها
images/scenes/partNN/       ← تأییدشده‌ها (ردشده‌ها در _rejected/)
images/_incoming/           ← تازه‌ساخته‌ها (کاربر می‌ریزد)
videos/clips/               ← کلیپ‌ها
premiere/                   ← خروجی ادیتور (بخش ۱۱)
audio/fa  audio/en          ← صدای هر خط (IMG045-1_ab12cd34.mp3) و voices.tsv (مدل و لحن هر صدا)
```

## ۵) قالب `story.txt`
هر خط «کلید: متن»؛ خط‌های `#` توضیح‌اند.
```
speaker: علی | #ef6c00 | charlie | جوان و شیطون   ← بالای فایل: نام | رنگ | صدا | لحن پیش‌فرض (لحن اختیاری)
=== scene-01 | هوک | 0:00-0:15 ===     ← شناسهٔ انگلیسی، عنوان فارسی، زمان
env: محیط صحنه
fx: توصیهٔ ادیت کل صحنه
[IMG001]                                ← جای تصویر؛ هر act/say زیرش تا [IMG] بعدی دقیقاً مال همین تصویر است
status: redo                            ← ok | redo | anim
pick: edfa6fe0                          ← نسخهٔ نهایی که کاربر انتخاب کرده (شناسهٔ تصادفی Flow؛ انتخاب = تأیید). شکل قدیمی (اسم فایل) هم خوانده می‌شود
off: yes                                ← زیر [IMG###] یا زیر سرصفحهٔ صحنه: کنار گذاشته شده (چیزی پاک نشده)
image-stale: yes                        ← پرامپت عوض شده، تصویر کهنه است
note: یادداشت کاربر
format-issue: مشکل فرمتِ همین قسمت
act: توضیح صحنه                       ← برچسب اختیاری: «act: گگ | شوخی بی‌صدا»
say: علی (با تعجب) | دیالوگ فارسی      ← «گوینده (لحن) | متن»
id: IMG045-1                            ← شناسهٔ ثابت همین دیالوگ (درست زیر say:؛ اسم فایل صدا از اینجا می‌آید)
en: English text of the line above      ← ترجمه، زیر خط فارسی (و زیر id:)
voice: fa=eleven-v3, en=default         ← صدای نهایی همین خط (زبان=نسخه)؛ صفحه می‌نویسد، من دست نمی‌زنم
voice-stale: fa                         ← صدای همین خط کهنه است (متن عوض شده)؛ صفحه می‌نویسد و پاک می‌کند
```
- **زبان:** `env`، `act`، `note` فارسی؛ فقط `say` ترجمهٔ `en:` می‌گیرد. گگ نوع جدا نیست، یک `act` با برچسب «گگ» است.
- **شناسهٔ دیالوگ (`id:`):** هر `say:` یک `id:` ثابت دارد و فایل صدایش با همان نام ذخیره می‌شود (`audio/fa/IMG045-1_ab12cd34.mp3`). با اضافه، حذف یا جابه‌جا شدن دیالوگ‌ها شناسهٔ بقیه هیچ‌وقت عوض نمی‌شود. **من:** `id:` را هیچ‌وقت عوض یا دوباره‌شماره‌گذاری نمی‌کنم؛ دیالوگ را که جابه‌جا یا حذف می‌کنم، `say:`، `id:` و `en:`اش را با هم می‌برم. برای دیالوگ تازه `id: IMGnnn-k` می‌نویسم: `IMGnnn` همان تصویریست که خط زیرش است و `k` اولین شمارهٔ آزاد همان تصویر (شمارهٔ خط حذف‌شده یا صدادار دوباره داده نمی‌شود). شکل قدیمی `L007` فقط خوانده می‌شود؛ `python tools/migrate.py` (اول بدون تغییر، گزارش می‌دهد) پروژهٔ قدیمی را به شکل تازه می‌برد. پروژه‌های قدیمی بدون `id:` همان شناسهٔ قبلی (`IMG001_2`) را دارند و صفحه موقع اولین اضافه یا حذف دیالوگ، همان را صریح می‌نویسد.
- **گوینده:** هر نامی توی `say:` باید خط `speaker:` بالای فایل داشته باشد (صدا از فهرست ElevenLabs مثل george، charlie، sarah). نام و لحن نباید `|` یا پرانتز داشته باشند.
- **مالکیت:** هر `act:`/`say:` مال نزدیک‌ترین `[IMG###]` بالای خودش است؛ چند `[IMG]` پشت‌سرهم بلوک مشترک نمی‌سازند (خط‌های بعدشان مال آخری‌اند). زیر سرصفحهٔ صحنه و بالای اولین `[IMG]` فقط `env:`، `fx:` و `off:` می‌نویسم؛ `act`/`say` آنجا هنوز خوانده می‌شود ولی صفحه هشدار می‌دهد.
- **صدا:** نام فایل همان `id:` است و صدای تازه `<id>_<8 رقم hex>.mp3` ذخیره می‌شود (هر بار ساخت یک نسخهٔ جدا؛ مدل، صدا، لحن و زمان در `audio/<زبان>/voices.tsv`). نام‌های قدیمی `<id>.<مدل>.mp3` و `<id>.mp3` هم نسخه حساب می‌شوند. خط بدون `id:` (پروژهٔ قدیمی) نام قدیمی `{اولین تصویر بلوکِ قدیمی}_{شمارهٔ خط}` را دارد (`IMG001_2`؛ قبل از اولین `[IMG]`: `scene-01_1`) و صفحه موقع اضافه یا حذف دیالوگ آن را صریح می‌نویسد. من برای هر `say:` تازه `id:` می‌نویسم.
- **کلیدهای صدا:** `voice:` و `voice-stale:` زیر همان `say:` (بعد از `id:` و `en:`) می‌آیند. شکل قدیمی (`voice-pick:` و `voice-stale:` زیر سرصفحهٔ صحنه) هنوز خوانده می‌شود و صفحه موقع اولین نوشتن، همان ورودی را به خط خودش می‌برد و از خط صحنه برمی‌دارد. خودم هیچ‌کدام را دستی نمی‌نویسم.
- **ویرایش توی صفحه:** کلیک روی متن، ویرایش، Enter؛ فقط متن بعد از «کلید:» عوض می‌شود. افزودن صحنه، تصویر یا خط جدید (به‌جز `en:`) با من است، نه صفحه. اگر همزمان یک خط را بیرون از مرورگر عوض کنیم، صفحه ذخیره نمی‌کند (صفحه را دوباره بارگذاری کن).
- **⚑:** دکمهٔ کنار هر قسمت `format-issue:` می‌گذارد. خط با قالب ناشناخته توی صفحه قرمز است.

### نسخه‌ها، انتخاب نهایی و ترتیب صحنه‌ها
- **عکس:** هر شناسهٔ تصادفی Flow یک نسخه است (`IMG004_slug_edfa6fe0_2K.jpg`)؛ فایل بی‌شناسه هم یک نسخه است. `_1K` و `_2K` و `_4K` با همان شناسه یک نسخه‌اند و بهترین کیفیت (۴K، بعد ۲K، بعد معمولی) نشان داده و خروجی گرفته می‌شود؛ تکراری مرورگر (` (1)`) نادیده است. بعد از اسم پایه (`IMG004`) باید `_` یا پایان اسم بیاید (`IMG0041` تصویر دیگری است). زیرپوشه‌ها بازگشتی خوانده می‌شوند (به‌جز `archive` و `_rejected` و `inbox`). کاربر با ◀ ▶ می‌گردد و آخرین نسخه‌ای که رویش می‌ایستد با `pick:` (شناسهٔ تصادفی) ثبت می‌شود و همان **تأییدشده و نهایی** است؛ آمدن فایل ۴K همان نسخه، انتخاب را حفظ می‌کند و فقط فایل نمایش را بهتر می‌کند. بدون `pick:` جدیدترین نسخه نهایی حساب می‌شود. برای انتخاب هیچ فایلی جابه‌جا یا عوض اسم نمی‌شود. الگوی اسم را می‌شود در `kit-config.json` (کلید `name_pattern`) عوض کرد.
- **صدا:** صدای هر مدل فایل جدا دارد: `audio/fa/IMG001_1.eleven-v3.mp3` (فایل بدون اسم مدل = قدیمی، با نام `default`). صدای مدل دیگر هیچ‌وقت روی قبلی نمی‌نشیند. صدایی که کاربر آخر می‌گذارد زیر همان خط توی `voice:` ثبت می‌شود و **صدای نهایی** است (بدون آن: `default`، وگرنه قدیمی‌ترین؛ نام تازه `IMG001-1_<rid>.mp3` هم یک نسخهٔ همان خط است)؛ ساخت صدای تازه هم خودش نهایی می‌شود.
- **جابه‌جایی تصویر:** تصویر = خط `[IMG###]` و همهٔ خط‌های زیرش تا `[IMG]` یا سرصفحهٔ بعدی (یادداشت، `pick:`، دیالوگ‌ها با `id:` و `en:` و `voice:`). برای جابه‌جایی، کل همین بلوک را با هم می‌برم و جای دیگر می‌گذارم؛ بلوک را نصفه نمی‌برم و خطی را کپی یا حذف نمی‌کنم. اگر بلوک را از زیر یک `=== scene ===` به زیر سرصفحهٔ دیگر ببرم، تصویر جزو آن صحنه می‌شود (صحنه فقط یک خط نشانه است). بین دو صحنه دقیقاً یک خط خالی می‌گذارم. اسم هیچ فایلی عوض نمی‌شود. پیش از جابه‌جایی، `id:` خط‌هایی که ندارند را با همان نام قبلی (`IMG001_2`) صریح می‌نویسم و `voice-pick:`/`voice-stale:` قدیمی صحنه را زیر خط‌های خودشان می‌برم، وگرنه صدا گم می‌شود. صفحه همین کار را با `POST /api/move` می‌کند و `POST /api/undo` برش می‌گرداند. صحنهٔ تامبنیل (`scene-00`) تصویر نمی‌گیرد و نمی‌دهد.
- **شروع و پایان صحنه:** صحنهٔ تازه = یک خط `=== scene-NN | عنوان | - ===` (شمارهٔ بعدیِ آزاد) درست بالای `[IMG]`ی که صحنه از آن شروع می‌شود، با `env:` اختیاری زیرش. برداشتن صحنه = پاک کردن فقط همان سرصفحه و خط‌های `env:`/`fx:`/`off:`ش؛ تصویرها می‌روند توی صحنهٔ قبل. شناسهٔ تصویر سه یا چهار رقم است (`IMG045`، `IMG1000`)؛ `IMG0451` با `IMG045` یکی نیست. تصویری که فایل یا پرامپت دارد ولی `[IMG###]` ندارد را با نوشتن همان `[IMG###]` سر جایش می‌گذارم (شناسهٔ تازه نمی‌سازم).
- **صحنه‌ها:** ترتیب نهایی = ترتیب بلوک‌های `=== scene-NN ===` توی فایل، نه شمارهٔ شناسه؛ شمارهٔ نمایشی هر صحنه جایگاهش است. کاربر می‌تواند صحنه را بالا و پایین ببرد (فقط بلوک جابه‌جا می‌شود، اسم هیچ فایل یا شناسه‌ای عوض نمی‌شود)، با `off: yes` کنار بگذارد و برگرداند، یا صحنهٔ جدید (با چند جای خالی تصویر) بعد از صحنه‌ای اضافه کند.
- **آرشیو:** فایل آرشیوشده به `images/archive/` و `audio/<زبان>/archive/` می‌رود (پاک نمی‌شود). من این پوشه‌ها را نادیده می‌گیرم؛ کاربر از روی صفحه برشان می‌گرداند.
- **قانون من:** صحنه یا تصویری که `off: yes` دارد را نادیده بگیر (ادیت، صدا، زیرنویس) ولی هیچ‌وقت متن یا فایلش را پاک نکن. تصویرِ جدیدِ بدون پرامپت یعنی کاربر جایش را ساخته: بپرس و پرامپت کامل برایش بنویس.

## ۶) کار من (هوش مصنوعی) و حلقهٔ بازبینی
1. اول توی `story.txt` جستجو کن: `format-issue`، `voice-stale` (هر خط کهنه)، `image-stale`، `status: redo`، `note:`. `format-issue` را رفع و خطش را پاک کن.
2. با `git diff` ببین چه عوض شده و ساده بگو: «دیالوگ عوض شده، صدا دوباره ساخته شود» یا «پرامپت/توضیح عوض شده، تصویر دوباره ساخته شود؛ پرامپت را اصلاح کنم؟». کاری را خودکار انجام نده، بپرس.
3. هر وقت دیالوگ یا پرامپت را عوض کردم، همان پرچم `*-stale` را می‌گذارم. با دکمهٔ «به‌روز شد» پاک می‌شود.
4. **حلقه:** کاربر پرامپت را کپی و در Flow می‌سازد ← خروجی را در `images/_incoming/` می‌ریزد ← «بررسی کن» ← من خوب‌ها را به `images/scenes/partNN/` و ردشده‌ها را به `_rejected` می‌برم ← `status: redo` = پرامپت را اصلاح کن، `ok` = تمام، `anim` = مرحلهٔ بعد، `note:` = خواستهٔ کاربر ← پرامپت اصلاح‌شده را در چت می‌دهم.
5. بعد از هر مرحله commit بگیر.
6. **صدا:** `tools/tts.py` موقتی است. صدا نساز، فقط بگو کدام صحنه نیاز دارد. ساخت دستی: `python tools/tts.py fa|en [id ...]`.
7. **پروژهٔ جدید:** فایل‌های موتور را کپی کن، پوشه‌ها را بساز، سناریو را به قالب بالا دربیار.

## ۷) ارسال پرامپت در چت (اجباری)
1. هر تصویر = دقیقاً یک بلوک کد؛ هیچ چیز لازم برای ساخت بیرون بلوک نماند.
2. خط اول بلوک `[REFS TO ATTACH: ...]` است، بعد به‌ترتیب بخش ۲.
3. هدر `=== IMG### ===` جزو بلوک نیست؛ فقط عنوان بالای بلوک.
4. متن بلوک انگلیسی؛ توضیح و عنوان فارسی و بیرون بلوک.
5. اگر پرامپت اصلاح شد، `prompts/prompts.txt` هم همان لحظه اصلاح شود (و `image-stale` گذاشته شود) و همان متن در چت داده شود.

## ۸) سبک و رنگ
- منبع سبک: `skills/image-style-skill.txt`؛ متن سبک داخل همهٔ پرامپت‌ها باید با آن هم‌خوان باشد.
- عبارت `fully colored, never washed out` را نگه دار. کلمه‌های `faint`، `pale`، `less saturated` ممنوع (به‌جز در همین جملهٔ منفی).
- صحنه‌های کرم/سفید زیاد خودشان کم‌رنگ درمی‌آیند؛ توی `Subject:` رنگ مشخص بنویس (مثلاً «walls in warm yellow, curtains and floor in rich colors»).
- نوشته: فقط «بدون حروف» بنویس و بگو سطح‌ها خط‌خطی یا نماد ساده باشند؛ اسم شهر یا کلمه‌ای که نباید ظاهر شود را صریح در پرانتز بیاور.

## ۹) پرامپت ویدیو (تصویر به ویدیو)
- جا: `prompts/video-prompts.txt` با همان هدر `=== IMG### ===`. هر بلوک کامل و مستقل؛ تصویر همان شناسه فریم اول است («Frames to Video» در Flow).
- ساختار بلوک (انگلیسی، به همین ترتیب):
  1. `[REFS TO ATTACH: ...]` دقیقاً مثل پرامپت تصویر همان شناسه.
  2. `[START FRAME: IMG###]`
  3. پاراگراف ثابت «حفظ سبک»: همان تصویر را متحرک کن، همان طراحی و رنگ، دوبعدی، شخصیت‌ها دقیقاً همان (قوانین ثابت پروژه اینجا هم تکرار شود).
  4. `Characters (exactly as in the attached reference images):` اسم هر شخصیت با توضیح کوتاه. توی `Action:` هم اسم رفرنس بنویس (`CH_MIMO` نه «میمو»).
  5. `Shot:` مدت (پیش‌فرض ۸ ثانیه)، 16:9، حرکت دوربین.
  6. `Action:` حرکت‌ها به ترتیب زمان؛ فقط یک ایدهٔ اصلی.
  7. `Ending:` ژست آخر (برای چسباندن به تصویر بعدی).
  8. `Sound:` بدون حرف و موسیقی؛ فقط افکت ملایم کارتونی.
  9. `Avoid:` اسم رفرنس به‌صورت متن، شخصیت جدید، نوشته، لب‌خوانی، سه‌بعدی، عوض شدن سبک یا چهره.
- فایل ویدیو با شناسهٔ تصویر شروع شود (`videos/clips/IMG008_race.mp4`)؛ ویدیوی رفرنس با اسم رفرنس. صفحه خودش دکمهٔ «▶ ویدیو» می‌گذارد؛ جدیدترین فایل نشان داده می‌شود و `_rejected` نادیده گرفته می‌شود.

## ۱۰) توصیهٔ ادیت (`fx:`)
- توصیهٔ کاربر برای ادیت، نه پرامپت؛ فارسی آزاد و کوتاه. **فقط استثنا را بنویس**، پیش‌فرض‌ها خودشان اعمال می‌شوند.
- دو جا: زیر سرصفحهٔ صحنه (قبل از اولین `[IMG]`) = کل صحنه؛ زیر `[IMG###]` = همان نما.
- واژه‌های مشترک:
  - دوربین: «حرکت آهسته»، «زوم آهسته روی ...»، «پن به چپ/راست»، «زوم سریع»، «پارالاکس»، «زوم به داخل ...»
  - گذار: «فید از سیاه/به سیاه»، «دیپ به سفید»، «کراس‌دیزالو»، «باز شدن کشو»، «وایپ کاغذ پاره»
  - حال: «وینیت»، «لرزش»، «فریز»، «اسلوموشن»، «تار شدن پس‌زمینه»
  - نور و ذرات: «نور/درخشش روی ...»، «چشمک نور»، «ذرات: گرد و غبار / حباب / جرقه / قلب / برف / ستاره»، «خطوط سرعت»
  - صدا: «صدا: ووش / ضربه / تیک / زنگ / باد / آتش / سکوت»، «موسیقی: ...»
  - «ویدیو»: این نما با کلیپ ساخته‌شده پر شود، نه عکس ثابت.
- پیش‌فرض‌ها (سبک «مستند مصور»، شدت ۳ از ۵):
  1. هر عکس «حرکت آهسته» دارد (۱ تا ۲ درصد در ثانیه)؛ هیچ نمایی کاملاً ساکن نیست.
  2. طول نما = طول صدای بلوک + نیم ثانیه؛ نمای بی‌صدا حدود ۳ ثانیه.
  3. بین نماها کات ساده یا کراس‌دیزالو کوتاه؛ بین صحنه‌ها «فید» یا «باز شدن کشو».
  4. هر `act` با برچسب «گگ»: «زوم سریع» + «صدا: ووش».
  5. ذرات متناسب با محیط، کم و آرام.
  6. صدای راوی بلندتر از موسیقی؛ بلندی نهایی −14 LUFS.
  7. ممنوع: فلش، گلیچ، کات خیلی تند، افکت روی صورت یا متن مهم.
- مثال: `fx: زوم آهسته روی صورت میمو، آخرش لرزش کوتاه؛ صدا: تپش قلب`

## ۱۱) خروجی پریمیر و تحویل پروژه به ادیتور
- **جای خروجی:** پوشهٔ `premiere/` کنار پوشه‌های اصلی پروژه، با سه چیز: فایل XML (`EP01_<زبان>_premiere.xml`)، یادداشت ادیت (`EP01_<زبان>_edit-notes.txt`) و پوشهٔ `media/` **فقط برای چیزهای ساخته‌شده** (لایه‌های شفاف، افکت صدا، صدای پس‌زمینه).
- **عکس و صدا کپی نمی‌شوند.** XML مستقیم به `images/` و `audio/` خود پروژه اشاره می‌کند، مثل `../images/scenes/IMG001_x.jpg`.
- **مسیرها همیشه نسبی‌اند** (از پوشهٔ خود XML)، هیچ‌وقت `D:\...` یا `file://localhost/...`. این‌طوری پروژه هر جای کامپیوتر ادیتور باشد باز می‌شود. (حدس: پریمیر مسیر نسبی را بدون خطا باز می‌کند؛ هنوز تست نشده. اگر آفلاین شد: راست‌کلیک روی کلیپ ← Link Media.)
- **رندرها و پیش‌نمایش‌های خودمان** (preview، demo، پلن) هیچ‌وقت توی `premiere/` یا پوشهٔ تحویلی نمی‌آیند؛ جایشان `videos/final/EP01_<زبان>_renders/` است. `videos/` توی گیت نمی‌رود (`.gitignore`).
- **خروجی از خود کیت:** `python tools/premiere_export.py --lang fa|en` (اختیاری: `--absolute`، `--fps`، `-o`) یک تایم‌لاین ساده می‌سازد: هر تصویرِ `off`نشده یک فریم ثابت (نسخهٔ انتخابی با بهترین کیفیت) به اندازهٔ جمع صداهای دیالوگش (بدون فایل صدا: برآورد از متن)، و صداهای انتخابی روی یک ترک صدا. مسیرها پیش‌فرض نسبی‌اند. اسمش عمداً `premiere_export.py` است تا `tools/export_premiere.py`ِ خودِ پروژه با به‌روزرسانی عوض نشود.
- **بعد از مهاجرت صداها:** `python tools/migrate.py --apply` مسیر صداهای عوض‌شده را داخل XMLهای پروژه هم درست می‌کند. XML قدیمی‌ای که از جای دیگر آمده: `python tools/premiere_check.py --fix` (از روی `.kit/renames.tsv`).
- **چک خودکار:** بعد از هر ساخت XML این را بزن و تا «OK» نشد تحویل نده:
  `python tools/premiere_check.py` (هر فایلی که XML لازم دارد باید باشد، و مسیر مطلق گزارش می‌شود).
- **تحویل به ادیتور:** `python tools/pack.py` یک zip کنار پوشهٔ پروژه می‌سازد: کیت + سناریو + عکس‌ها + صداها + پکیج پریمیر، بدون رندرها، ویدیوهای خروجی، آرشیو، `.env` و کلیپ‌ها (کلیپ‌ها با `--clips`). اگر XML فایلی بخواهد که توی zip نیست هشدار می‌دهد.
