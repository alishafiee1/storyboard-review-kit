## 1.21.0
- Downloads watcher (new engine file `tools/watch.py`): `python tools/watch.py` watches the folder every few seconds (`--once` = one pass, `--dry-run` = only report, `--downloads DIR`); the folder is `kit-config.json` `downloads` (default `~/Downloads`, Windows and Linux). `serve.py` runs it in a background thread when `kit-config.json` has `"watch_downloads": true` (default false). A file is MOVED (cut, never copied) only if its name parses with the Flow pattern, its base is known in this project (`[IMG]` marker, prompts.txt header, or an existing reference) and, with `match_slug` (default true), its slug fits the expected output name: `[OUTPUT NAME: IMG045_cave_wall]` in the prompt, else the slug of the versions on disk (case, underscores and Flow's `…` cut-off ignored; a file with no slug fits; a file with a slug but nothing to compare it with stays). Scene pictures go to `images/scenes/bNN/` (IMG001-010 = b01, IMG000 = b00), references to `images/refs/<KIND>/` (CH, LOC, PROP, STYLE, GRP, CAR). Partial downloads (`.crdownload`, `.part`, `.tmp`, or size/time changing during the pass) are skipped. Nothing is overwritten: identical bytes already in the project -> the Downloads copy is removed; same name with other bytes -> ` (n)`. Cross-drive moves use `shutil.move` to a `.tmp` and `os.replace`. Every move is appended to `.kit/imports.tsv` (time, from, to, size). Everything else in Downloads is never touched.
- `GET /api/imports` (last imports, whether the watcher runs, the folder). `GET /api/project` has new keys `inbox` (files of `inbox/` with `name`, `size`, `kind` guess), `triage` and `imports`. The references tab lists them (only when there is something to list).
- Odd files in `images/refs/` (names that do not parse as a reference, e.g. a browser's cut-off name) are no longer shown as references; they are listed as `triage` ("needs sorting"). Behaviour change for old projects that relied on the cleaned-up name.
- Batch prompts (new engine file `tools/batch.py`): `python tools/batch.py b05` / `GET /api/batch?b=b05` (JSON `{batch, ids, text, missing}`; `&format=text` = plain text): for each picture of the batch in story.txt or prompts.txt, in number order: `=== IMG045 ===`, the `[REFS TO ATTACH: ...]` line with the real reference file names (best version on disk), the prompt, and `Output name: IMG045_<slug>`.
- `flowname.config(root)` / `settings(root)` take an optional project root; new `output_slug()`, `slugs_match()`, `REF_KINDS`. AI guide (`how-to-write-prompts-for-flow.md`, `starter/CLAUDE.md`): `[OUTPUT NAME: ...]` line, watcher and batch, how to triage `inbox/` (rename, move, log in `.kit/imports.tsv`, never delete). `starter/inbox/` added.
- Tests: 22 new unit tests (`test_intake.py`: move to bNN / refs kind, wrong slug / unknown base / strangers untouched, tolerant slug match, partial and growing files, collisions, identical duplicate, log, dry run, simulated cross-drive move, files put by hand in any subfolder, refs triage, inbox, batch text) and 1 new browser test (inbox / triage / imports in JSON and page, `/api/batch`, the server's watcher thread). `baseline/project.json` changed on purpose (new keys `imports`, `inbox`, `triage`); one test in `test_versions.py` changed on purpose (odd refs file is no longer a reference). 166 unit and 48 browser tests in total.

## 1.20.0
- Migration (new engine file `tools/migrate.py`): `python tools/migrate.py` is a dry run (the default): nothing changes, a full Markdown report is printed and saved to `.kit/migrate-report-<time>.md`. `--apply` first copies `scenario/story.txt` and every `*.xml` of the project (not `.git` / `.engine-backup`) to `.engine-backup/migrate-<time>/`, then gives every dialogue line an image-based id `IMGnnn-k` (nnn = the picture the line sits under, k = its position among that picture's lines; ids already in that form are kept; a taken k moves on) and renames the voice files of every `audio/<lang>/` folder, recursively, `archive/` included (`_samples/` and `_tests/` untouched): `IMG001_1.mp3` -> `IMG001-1.mp3`, `IMG001_2.eleven-v3.mp3` -> `IMG001-2.eleven-v3.mp3`, `L007.mp3` -> `IMG045-1.mp3`; the model tag, random id or ` (1)` stays. The line's choice goes under the line (`voice:` / `voice-stale:`, via the same `pin_scene` as moves), old scene-level `voice-pick` / `voice-stale` entries move there, `voice:` values that were file names follow the renames, and entries that name no line stay where they are. Shared-block lines stay under the last `[IMG]` of the block (listed in the report). Every rename is appended to `.kit/renames.tsv` (`time<TAB>old<TAB>new`). A target name that is already taken is never overwritten: that line keeps its old id and files and the report says so. `--undo <time>` renames everything back and restores story.txt and the XMLs byte for byte (refuses when they changed since, unless `--force`). `--apply` refuses a git project with uncommitted changes (`--allow-dirty` overrides; the dry-run reports and `.engine-backup/` do not count as changes). A failure in the middle puts everything back.
- Premiere XML: `<pathurl>` of every XML that points at a renamed voice is rewritten, whether relative, `D:\...` or `file://localhost/D%3a/...` (URL-encoded); every other byte of the file stays. `python tools/premiere_check.py --fix [file.xml]` repairs XMLs from `.kit/renames.tsv` (chains A->B->C are followed; a copy of the old XML goes to `.engine-backup/premiere-fix-<time>/`) and then reports the missing files as before.
- New voices: `tts.py` writes `audio/<lang>/<id>_<rid>.mp3` (8 random hex; every take is a new version, nothing is overwritten or archived any more) and appends `file, model, voice, tone, time` to `audio/<lang>/voices.tsv`; the new take becomes the line's `voice:` choice. Without force, a line that already has a voice of that model (old `<id>.<tag>.mp3` or a `voices.tsv` row) is skipped. Reading the old names is unchanged.
- New dialogue lines get `id: IMGnnn-k` (the first free k of the picture the line is added to; ids in story.txt and voice files of any language, archive included, count as taken, so a number is never reused). Above the first picture the old `L001` form is still used.
- `tools/premiere_export.py` (new engine file): `python tools/premiere_export.py [--lang fa|en] [--absolute] [--fps 25] [-o out.xml]` writes a simple FCP7 xmeml timeline: each picture that is not set aside (not the thumbnail `IMG000`) is a still (picked version at best quality via `media.resolve`) as long as the sum of its dialogue voices (mp3 length read from the frames; a line with no voice file is estimated from its text; no dialogue = 3 s); the chosen voices are on an audio track. Paths are relative to the XML by default. It is deliberately not called `export_premiere.py`: a project that has its own `tools/export_premiere.py` would see it replaced by an update.
- `tools/update.py` prints a hint to run `python tools/migrate.py` (dry run) after an update; `.kit/migrate-report-*.md` joins the ignore rules (also `starter/.gitignore`). Note: the hint comes from the new `update.py`, so it first shows on the update after this one.
- Tests: new realistic fixture (`tools/tests/mimo.py`, `fixture/mimo-story.txt`: Flow-named pictures in part01 / part02, old voice names incl. `.eleven-v3` variants and `L007`, a shared block, scene-level voice-pick, an XML with `file://localhost/D%3a/...`, `D:\` and relative paths); 27 new unit tests (`test_migrate.py`: dry run changes nothing, apply, every voice resolves to the same bytes, XML byte-identical outside the pathurls, undo byte for byte, collisions, dirty git, `--fix`, new voice names + `voices.tsv`, new line ids, export) and 1 new browser test (the migrated fixture loads and every 🔊 button plays the same decodable audio; undo brings it back). Existing tests changed on purpose: three that expected `L001` for a new line now expect `IMGnnn-k`; the voice-making browser tests expect `<id>_<rid>.mp3` and no archiving. Baselines unchanged (144 unit and 47 browser tests in total).

## 1.19.0
- Moving pictures (new engine file `tools/moves.py`): `POST /api/move {"ids": ["IMG004", ...], "before": "IMG002"}` (or `"after"`, or `"to_end_of_scene": "scene-03"`; exactly one) moves the `[IMG]` line and everything that belongs to it (note, status, pick, fx, prompt-stale flag, dialogue lines with their `id:` / `en:` / `voice:` / `voice-stale:`) up to the next `[IMG]` or scene header, also across scene headers: the picture then belongs to the destination scene. Several ids keep the order they have in the file. Onto itself (or to where it already is) changes nothing and keeps no snapshot. The thumbnail scene `scene-00` neither gives nor takes pictures. Exactly one blank line stays between scenes; lines are only moved, never copied or dropped. No file on disk is renamed; prompts, picked versions and voice files follow the picture because they are keyed by its id.
- Before anything moves, the scenes involved (source and destination) get their old position-based line ids written out (`id: IMG001_2`) and their old scene-level `voice-pick:` / `voice-stale:` entries moved under the lines they are about, so no voice changes name, file or choice. Scenes that are already in the new form change by nothing but the move.
- `POST /api/scenemark`: `op: "insert"` `{before: IMG, title, env?}` starts a new scene at that picture (takes it and the pictures after it; id = next free `scene-NN`; the number shown on the page stays the order); `op: "remove"` `{scene, force?}` deletes only the header (the pictures join the previous scene); it refuses without `force` when the header has `env` / `fx` / `off` / `model` lines, always when other text sits above its first picture, and for `scene-00` or a scene right after it; `op: "edit"` `{scene, title?, env?, fx?, old?}` (an `old` that no longer matches is a 409).
- `POST /api/addimage` takes a position: `{after: IMG}`, `{before: IMG}` or the old `{scene}` (end of the scene), and an optional `{id: "IMG045"}` for a picture id that has files or a prompt but no marker yet (409 when it already has one). New ids still come from `next_image_id`.
- Picture ids may have four digits: `[IMG1000]` is read everywhere (`MARKER`, `next_image_id`, the API checks, `pack.py`, file-name fallback); the limit is 9999. `IMG0451` stays another picture than `IMG045`.
- All three endpoints are structural: a snapshot goes to `.kit/history/` first, `POST /api/undo` gives the bytes back, and a picture or scene that is no longer in the file answers 409.
- Page (minimal hooks, the redesign comes later): each picture has a `⋯` menu with «one image up / down» (over a scene header too, skipping scenes that are set aside), «new picture after this», «start a new scene here» and «join the scene above» (the first picture of a scene). The page HTML baselines changed on purpose (the new menu).
- Tests: 28 new unit tests (`tools/tests/test_moves.py`: move within a scene, across scenes, several ids, first / last place, around `scene-00`, legacy ids and scene-level choices travelling, multiset of lines, undo byte for byte, 409) and 2 new browser tests (117 unit and 46 browser tests in total).

## 1.18.0
- Flow file-name reader (new engine file `tools/flowname.py`): picture and reference names like `IMG001_hook_bench_passersby_edfa6fe0_2K.jpg`, `LOC_FACTORY_YARD_4eb46d68.jpg` or `IMG018_dna_bookshelf_8c45285a.jpg` are read as base + optional slug (a trailing `…` is fine) + optional 8-hex random id + optional quality (`_1K`/`_2K`/`_4K`, any case) + the browser's ` (1)` copy counter. The separator after the base is required, so `IMG0451` is its own image and never a version of `IMG045`; names that do not follow the pattern but start with `IMG###` (old projects) still belong to that image as their own version. The pattern can be replaced per project in an optional `kit-config.json` at the project root: `{"name_pattern": "<regex with the named groups base, slug, rid, q>", "quality": ["4K", "2K", "1K"]}`; a missing or broken file falls back to the default.
- Versions: one version = `(base, rid)`; without a rid `(base, slug)`; a bare file `(base, "")`. All quality files of a version are ONE version and the best one is shown / exported (4K, then 2K, then 1K, then the plain file); a ` (1)` copy is never shown while its original exists. The page's `◀ ▶` counter counts versions, not files, and shows the quality (`2 / 3 · 4K`). Versions in `GET /api/project` carry `id`, `q` and `files`; every image carries `batch` (`IMG001`–`IMG010` = `b01`, `IMG011`–`IMG020` = `b02`, `IMG000` = `b00`).
- `pick:` stores the random id (`pick: edfa6fe0`; for a version without one, the file name). Old values (a file name, any quality of the version) still find their version and are written as the id the next time the page picks. When a better file of the picked version arrives (a `_4K`), the pick and the approval stay and the shown file changes; nothing is ever renamed. Archiving a version moves all its quality files together.
- Scans are recursive: `images/scenes/`, `images/refs/` and `audio/<lang>/` are read at every depth (`partNN` and `bNN` folders alike), leaving out `archive/`, `_rejected/` and `inbox/` (rejected pictures are still listed as «rejected»). A reference appears once, with its newest version at best quality.
- Voices follow the same rule: `IMG045-1_<rid>.mp3` (new), `<id>.<model>.mp3` and `<id>.mp3` (old) are variants of one line (`default` first, then oldest first); a ` (1)` copy is ignored. `voice:` picks the rid, the model tag or `default`. The tts maker still writes `<id>.<model>.mp3` (the new names come with the migration phase).
- One resolver, `media.resolve("image" | "voice", id, pick, lang)`, answers «which file?» for the page, the subtitles and `pack.py` (which now also prints a hint when a Premiere XML points at a picture that is not the picked, best-quality file); the Premiere export will use it too. `audio_index(lang)` reads the voice folder once per build.
- Tests: 27 new unit tests (`tools/tests/test_versions.py`, fake-file fixture with 2K + 4K + plain of one rid, ` (1)`, `…`, `IMG0451`, pick by old file name, pick by rid surviving a new 4K, recursive scan, voices, config) and 1 new browser test (89 unit and 44 browser tests in total). The `project.json` baseline changed on purpose (new fields `batch`, version `id` / `q` / `files`, reference `versions`); the page HTML baselines did not change.

## 1.17.0
- Safety: before every structural edit (add or delete a line, add a picture or a scene, move or set aside a scene) `scenario/story.txt` is copied, byte for byte, to `.kit/history/` (the last 30 are kept). `POST /api/undo` puts the newest copy back and removes it from the history (`{"id": ...}` = the snapshot the caller thinks is the newest; 409 if it differs, or if story.txt was changed after that edit unless `{"force": true}`; the file as it was goes to `.kit/undone/`). `.kit/` starts with a dot, so it is never served; `.kit/history/` and `.kit/undone/` are in the ignore rules of `update.py` and also carry their own `.gitignore`. `GET /api/project` lists the snapshots (`history`). Line names without `id:` are computed exactly as before (`IMG001_2`, named after the first picture of the old shared block), so the same audio plays.

The old scene-level `voice-pick:` / `voice-stale:` are still read (mapped onto the lines); every new write uses the per-line form and moves only the entry it touches off the scene-level line. A changed line now marks only itself out of date; a new line starts out of date; changing a speaker's voice marks that speaker's lines.
- Line endpoints (`/api/line`, `/api/add`, `/api/delete`, `/api/issue`) take `{"image": "IMG001", "index": n}` with `n` counted from the picture's own `[IMG001]` line (the old `{"scene", "index"}` still works). `/api/voicepick`, `/api/flag` and the voice dialog work by line id (the scene is optional). `/api/regen` makes the voices of the stale lines only: all of them, or `{"image": ...}` / `{"scene": ...}`; a made line loses its flag, a failed one keeps it. The page sends picture addresses; it looks the same.

## 1.7.0
- One config file for voices: `voices/voice-config.json` (models, voices per model, tones). Built automatically from an existing `voices/catalog.txt` the first time; «Refresh voice list» merges the API list into it and keeps your own fields (accent, gender, note, tested, tags). `catalog.txt` stays as the raw list.
- Tones come from that file (`fa` name, `match` aliases, English `tag`): `tools/tts.py` no longer has a built-in list, sends up to 2 tags per line, and warns (page alert + terminal) about a tone that is not in the file instead of silently sending nothing. A tone with an empty tag (e.g. «عادی») is known and sends nothing.
- Page: tone menu lists the config tones; unknown tones are red (line, speakers tab, banner); the scene model menu marks models that lack a speaker's voice.
- Fix: a voice name with `-` or `.` (Deepgram, AssemblyAI, MAI voices…) broke the `speaker:` line and could not be saved from the page.
- New `tools/voice_test.py`: makes the same sentence with chosen models, voices and tones (shows the cost first, nothing is made without `--yes`); `audio/_tests/index.html` lets you mark 👍 / 👎, saved into the config.
